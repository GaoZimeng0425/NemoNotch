# 核心哲学:用 AI 构建原生 macOS App

## TL;DR

> **不靠"模型很聪明"来保证质量,而靠强约束 + 收回脚手架所有权 + 负面清单 + 确定性兜底 + 可回滚。把"模型聪明"当锦上添花,把"工程兜底"当地基。**

这不是一句励志口号——它是贯穿 Ironsmith 每个工程决策的操作原则。每当你在下面任何分支点犹豫时,先问:"我有没有客观判据?有没有退路?"

---

## 可复用原则

### 1. 分档升级,贵的手段放后面

成本从低到高排列处理策略,永远先试便宜的:

```
确定性规则(免费)
  → 受限模型调用 / diff 修复(便宜)
    → 整体重生(贵)
```

Ironsmith 的修复循环(`ContentViewBuildRepairLoop`)把这三档硬编码为代码路径,而非依靠工程师的临时判断。不要把"试试模型能不能修"和"确定性修复"的顺序搞反。

### 2. 模型输出默认不可信

收到模型输出后的标准流程:

```
校验(结构 + 安全 + 禁止内容)
  → 应用(含容错匹配)
    → 验证是否变好(客观判据)
      → 不好就回滚
```

"客观判据"必须是可编程的——Ironsmith 用编译器错误数。如果你的判据是"看起来对",那就不算客观判据。

### 3. 永远留退路

三条具体操作:

- **记历史最优版本**(`recordBestCandidate`)——全流程失败时恢复它,不留最后那个烂摊子。
- **编辑前暂存,失败即恢复**——不允许"修改中途崩溃后留下半成品"。
- **失败预算化**——连续无效 N 次后切策略或放弃,不无限烧模型 token。

### 4. 默认安全、显式降级

- 沙箱默认开启。
- 敏感权限(camera、mic、automation)在 entitlements 中显式声明。
- 降级路径(关闭沙箱、使用全文件重写而非 diff)加醒目警告,不静默执行。

### 5. 收回脚手架所有权

**模型只动最小可编辑面。** 入口(`@main`)、包清单(`Package.swift`)、manifest 由你写死,不交给模型生成。模型只写 `ContentView.swift` 一个文件。

这是"不靠模型聪明"的直接体现:你不依赖模型"知道"入口文件不能乱改,而是直接不给它改的机会。

### 6. 源码和测试是唯一真相源

文档会漂移。在落地任何"文档里描述的机制"之前,先用 `grep` / 阅读确认对应文件/函数/标志仍存在。

## Pitfalls

- **把"模型通常能做对"当成工程保障**——通常能做对不等于总能做对,边界情况下模型会输出无法编译、含占位符或越界的代码。每一层校验都是在防那 5%。
- **退路是可选项**——很多团队在"一切顺利时"不维护回滚机制,等到出问题时才发现没有退路。把退路设计成默认行为。
- **文档即代码**——写给 AI agent 的工程指南如果有过时内容而不标注,AI 会把过时内容当真相。参见 I-22。
- **一开始就上贵的手段**——直接让模型整体重写比先跑确定性修复贵 10–100 倍,且成功率未必更高。

## 落地 Checklist

- [ ] 确定"客观判据"是什么(编译错误数、测试通过数、schema 校验……),在开始写代码前就决定。
- [ ] 写死脚手架文件,模型只能动最小可编辑面。
- [ ] 硬编码分档策略:确定性 → 受限模型 → 重生;不依赖运行时判断。
- [ ] 每次生成/编辑前先暂存当前版本;失败后有明确的恢复路径。
- [ ] 记录历史最优版本(不只是最后一个版本)。
- [ ] 为每个模型调用预设"预算上限"(次数、token、时间);超限即切策略。
- [ ] 沙箱默认开启;关闭沙箱是显式降级,加日志警告。
- [ ] 文档(包括 AGENTS.md / CLAUDE.md)标注哪些描述已验证、哪些可能过时,⚠️ 标记 drift。
